# Contributing to GDX Analyzer

## Development

```sh
npm install
npm run compile            # or: npm run watch
npm test                   # unit tests; also runs gdxdump/gdxdiff through each backend that is found
npm run test:integration   # tests inside a VS Code extension host
```

Press <kbd>F5</kbd> in VS Code to launch an Extension Development Host with `test/fixtures` open.

Environment variables for the tests:

| Variable | Purpose |
| --- | --- |
| `GDX_TEST_GAMS_DIR` | Directory with gdxdump and gdxdiff to compare with, and for the GAMS backend tests (found automatically otherwise) |
| `GDX_TEST_GAMSPY` | gamspy executable for the GAMSPy backend tests; also enables the GAMSPy integration test |
| `VSCODE_EXECUTABLE` | An installed VS Code for the integration tests instead of a downloaded one |
| `GDX_TEST_PYTHON` | A Python with GAMS Transfer (and GAMSPy) to run the generated code (default: the `.venv` of the repository) |

The fixtures in `test/fixtures` are generated by the `make_*.gms` files next to them; `native.gdx` and `formats/`
cover what the native GDX reader reads (see `make_native_fixture.gms`), and `pair1.gdx`/`pair2.gdx` what comparisons
find (`make_pair_fixture.gms`). When a GAMS system is found, the tests compare
the native reader with gdxdump on every fixture, record by record, its text dumps and CSV with gdxdump's output, and
its comparisons with gdxdiff's (summaries and difference files, with several option sets).
`samples/base.gdx` and `samples/scenario.gdx` are a pair to try the comparison on, and `samples/infeasible.gdx` is an
infeasible solution of the same model to try the solution report on (`samples/make_samples.gms`).

## Packaging

There is one package for all platforms: the extension reads, compares and dumps GDX files itself.

```sh
scripts/package.sh                     # dist/gdx-analyzer-<version>.vsix
```

## gdxdump and gdxdiff for the tests

The tests compare the extension's results with those of gdxdump and gdxdiff when they find them. Without a GAMS
system, fetch them from the `gamspy_base` wheels on PyPI (checked against their published digests, and
smoke-tested) and point the tests at them:

```sh
python3 scripts/fetch-gdx-tools.py linux-x64      # into tools/linux-x64 (also linux-arm64, darwin-x64, darwin-arm64, win32-x64)
GDX_TEST_GAMS_DIR=tools/linux-x64 npm test
```

The README's relative links and images are rewritten to the public GitHub repository (`repository` in
`package.json`) when packaging, so push new images to GitHub before publishing.

## Continuous integration

The GitLab pipeline (`.gitlab-ci.yml`):

1. runs the unit tests, with gdxdump and gdxdiff for Linux x64 to compare with,
2. packages the extension, and
3. on a tag matching the version in `package.json` (`v0.9.0` or `0.9.0`), publishes to the Visual Studio
   Marketplace and Open VSX. These are manual jobs that need the CI/CD variables `VSCE_PAT` and `OVSX_PAT`.

## Code layout

| Path | Contents |
| --- | --- |
| `src/extension.ts` | Activation and commands |
| `src/tools.ts` | Locating the tools, command lines for both backends, running processes |
| `src/gdxReader.ts`, `src/gdxFile.ts` | The native GDX reader, and reading GDX files with it or gdxdump |
| `src/gdxText.ts` | gdxdump's text output (normal format and CSV) written from the native reader |
| `src/gdxDiff.ts`, `src/gdxWriter.ts` | Comparing two GDX files as gdxdiff does, and writing GDX files (the difference file) |
| `src/parse.ts` | Parsers for the gdxdump and gdxdiff output |
| `src/table.ts` | Host-side table model: sorting, filters, windows of rows, table view, charts, comparisons |
| `src/query.ts` | Answers the webviews' queries (search, windows, charts, copying, selection statistics) |
| `src/format.ts` | Number formats and exact values |
| `src/viewer.ts`, `src/diff.ts` | The viewer (custom editor; files of other file systems are copied) and the comparison panel |
| `src/dump.ts` | Read-only `gdxdump:` documents |
| `src/export.ts`, `src/xlsx.ts` | Excel export (no dependencies) and GAMS Connect instructions |
| `src/codegen.ts` | "Copy as Code": Python (GAMS Transfer, GAMSPy) for a symbol and its view |
| `src/gdxQuery.ts`, `src/mcp.ts`, `src/mcpProvider.ts` | The MCP server for AI agents and its registration |
| `src/gdxRefs.ts`, `src/links.ts` | GDX file and symbol references in GAMS and Python source, and their links to the viewer |
| `src/preview.ts`, `src/hovers.ts` | Hover previews of GDX files and symbols in GAMS and Python source |
| `src/solutionReport.ts` | The solution report of all variables and equations of a file (viewer and MCP) |
| `src/scenario.ts`, `src/scenarios.ts` | The table of a symbol across scenarios, and the scenario comparison panel (`media/scenarios.js`) |
| `src/gitCompare.ts` | Comparing a GDX file with a Git revision (through the Git extension of VS Code) |
| `media/` | Webview scripts (`table.js`, `chart.js`, `viewer.js`, `diff.js`) and styles |
| `scripts/` | Packaging, and fetching gdxdump and gdxdiff for the tests |
